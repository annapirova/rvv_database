### Физическая архитектура (Storage Layer)

База данных реализует колоночную in-memory архитектуру. Все данные хранятся по столбцам в одной таблице и 
разбиваются на независимые горизонтальные блоки — "чанки" фиксированного размера. Внутри каждого чанка 
данные организованы по схеме SoA (Structure of Arrays). 
Каждый атрибут (столбец) представляет собой плотный, выровненный в памяти массив.

Особенности хранения полей метаданных:
1. __Числовые значения__ (id, размер, продолжительность, время загрузки и т.п.)
хранятся как неотсортированные массивы фиксированного размера. Вся таблица глобально упорядочена только по одному полю (id или время загрузки).
2. __Повторяющиеся строки__ (названия форматов, кодеки, авторы) кодируются по словарю Dictionary парами (id, значение). Сами строки хранятся в одном глобальном массиве.
В чанке таблицы хранится только числовой id.
4. __Уникальный текст__ (описания, названия, теги) хранится в виде двух параллельных массивов в чанке:
* description_blob (std::vector<char>) — единый массив символов, в котором все строки чанка идут друг за другом.
* description_offsets (std::vector<uint32_t>) — массив смещений фиксированного размера, указывающий на начало текста каждого файла.
4. __Векторные эмбеддинги__ (если будут): матрица вещественных чисел фиксированной размерности, упакованная в плоский массив.

### Устройство индексов и поисковых структур
Используем 3 структуры данных: хеш-таблица Swiss Hash Table, дерево FAST, префиксное дерево ART.
- __Swiss Hash Table__ используется для обращения к глобальному словарю повторяющихся строк.
- __FAST__ - числовой индекс - используется для быстрого поиска диапазонов чисел (WHERE size BETWEEN X AND Y) и точечного поиска по числовым ID.
- __ART__ - Инвертированный текстовый индекс, используется для полнотекстового поиска BM25.
Оно отображает Слово -> Список совпадений (Postings List).
Для __ранжирования__ используется реализация алгоритма BM25.

### Минимальный список нужных операторов SQL
1. __TableScan__ (Сканирование таблицы)
- Что делает: Начальный оператор. Читает данные из колоночного хранилища блоками по 1024 элемента и передает их вверх по цепочке.
2. __Filter__ (Фильтрация — оператор WHERE)
- Принимает чанк данных, применяет к нему условия
3. __HashJoin__ (Соединение — оператор JOIN)
- Что делает: Реализует соединение таблиц.
4. __FullTextSearch__ (Полнотекстовый поиск — оператор MATCH...AGAINST)
- Что делает: Передает токены поискового запроса в ART-индекс, извлекает списки документов
и считает формулу BM25 для всех строк в проходящем чанке. Добавляет виртуальную колонку score (рейтинг).
 5. __Limit__ (Ограничение выборки — оператор LIMIT)
- Что делает: Конечный оператор. Принимает чанки, упорядочивает их по колонке score (или timestamp) и останавливает выполнение всей цепочки, как только набралось нужные N результатов.

- Чтобы выполнение запроса было быстрым, необходим механизм планирования исполнения запроса!
